The kiosk is the screen passengers tap when they board. It checks their Bataeño Pass, shows **green (Welcome aboard)** or **red (Ride denied)**, and sends the tap to the server so the ride is counted.

## Two places the kiosk runs

The same kiosk code runs in two apps:

| | Boarding mode (in use now) | Standalone kiosk app (for later) |
| --- | --- | --- |
| Repository | `libresakay-driver-app`, module `kiosk/` | `libresakay-android-kiosk` |
| Device | The driver's phone | A Decard F10-X1 terminal fixed in the bus |
| Reads | Bataeño Pass QR code (camera) and cards (phone NFC) | Cards, through the terminal's built-in reader |
| Why | Terminals not delivered, cards not printed yet | The original design |

The `kiosk/` module is a near-copy of the standalone app's code, under the same package name (`com.example.librengsakay`). That's on purpose, so a fix in one can be copied to the other as a plain diff. **When you change kiosk code, check whether the other repository needs the same change.**

## Boarding mode

The driver opens boarding mode from the Trip tab. It fills the whole screen and looks exactly like the real kiosk, so the phone can be handed to passengers or pointed at their QR codes.

- **Camera and NFC run at the same time.** Both feed the same "one tap per person" check, so a QR held up to the camera for several seconds still counts once.
- The driver can pick the front or back camera, and turn on the flashlight at night.
- **Leaving needs a long press**, so a passenger can't fall into the driver's messages by accident. Settings has a switch to use a normal back button instead, for testing.
- The screen stays on while boarding mode is open.

Code: `app/.../ui/boarding/BoardingModeScreen.kt` hosts it. The kiosk itself starts up in `DriverApplication` alongside the driver app.

## The kiosk screens

| Screen | When |
| --- | --- |
| Enrollment | The phone hasn't been linked to a bus yet. See [Kiosk setup](/admin/kiosk-setup). |
| No shift assigned | Linked to a bus, but the bus has no shift today. |
| Waiting for trip | The bus has a shift, but the driver hasn't started the trip. Shows the bus, route and driver. |
| Tap your pass | A trip is running. Ready for passengers. |
| Welcome aboard (green) | Accepted. Shows name, photo and group (Senior Citizen, Student...). |
| Ride denied (red) | Refused, with the reason. |
| Trip not started (grey) | Someone tapped before the trip started. Nothing was counted. |

## Two identities on one phone

In boarding mode the phone holds **two separate keys**:

- the **driver's** key (from Bataeño Pass sign-in), tied to the driver, and
- the **kiosk's** key (from the enrollment code), tied to a **bus**.

These don't follow each other. If dispatch moves a driver to a different bus, the phone's kiosk is still linked to the old bus, and taps would land on the wrong trip. When a driver changes bus, an admin must **Rebind** the kiosk to the new bus, or enroll the phone again.

## Where the kiosk code lives

Inside `kiosk/src/main/java/com/example/librengsakay/` (and the same paths in the standalone app):

| Folder | What's inside |
| --- | --- |
| `kiosk/` | Screens, and `BoardingCoordinator`, which decides board / already boarded / get off for each tap |
| `nfc/`, `reader/` | Reading cards and QR codes. `TapGate` ignores the same pass shown twice within 2.5 seconds. |
| `api/` | `BataenoPassApi`, which asks Bataeño Pass whether a card or QR code is valid |
| `scanner/` | Talking to our server: enrollment, heartbeat, current trip, tap upload |
| `eligibility/`, `data/` | The on-phone lists used when there's no signal, and the queue of taps waiting to upload |

## The standalone kiosk app

`libresakay-android-kiosk` is the same kiosk built for the Decard F10-X1 terminal. Differences from boarding mode:

- It reads cards through Decard's own reader library (`reader/ReaderManager.kt`) instead of phone NFC. On other Android devices it falls back to phone NFC automatically.
- It locks the device to the kiosk app, starts when the bus powers on, and survives reboots. This needs the app set as "device owner" (see its README).

::warning
**Known blocker:** on the F10-X1 unit, opening the card reader still fails (`dc_open` returns `-1`). `libresakay-android-kiosk/CLAUDE.md` describes what's been ruled out and the next test to run. Read it before touching the reader code.
::

::caution
**Secret in the source code.** The Bataeño Pass client ID and client secret the kiosk uses to check passes are written directly in `telemetry/KioskConfig.kt`, in both Android repositories. Anyone with the code or the APK can read them. Move them out of the source (for example into Gradle properties that aren't committed), and ask the Bataeño Pass team for a new secret, since the current one has been in git history.
::
