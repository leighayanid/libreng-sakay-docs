Signing in and having access are two separate things.

- **Signing in** needs a Bataeño Pass account. Anyone can have one.
- **Access** comes from a **role** that an admin gives you. Without a role, a signed-in person can only use the passenger tracker.

## The roles

| Role | What they can do |
| --- | --- |
| **Super Admin** | Everything, including system settings, roles and audit logs. |
| **Admin** | Live monitoring, manage buses, drivers, routes, schedules, kiosks and announcements, message drivers, reports, audit logs. |
| **Dispatcher** | Manage buses, drivers, routes, schedules and kiosks, message drivers. No reports. |
| **Inspector** | Record bus inspections. |
| **Driver** | Use the driver app: start and end trips, read messages from dispatch. |
| **Scanner Operator** | Record passenger taps. Not given to people: each enrolled kiosk gets its own hidden account with this role (see [Kiosk setup](/admin/kiosk-setup)). |
| **Report Viewer** | View and export reports. |
| **Developer** | Use the partner developer portal at `/developers`. |
| **Passenger** | Use the passenger tracker. |

A person can have more than one role. Messaging is only between dispatch/admin and drivers, never driver to driver.

## How a driver gets access

A driver needs two things:

1. A **driver record**, created by an admin under **Drivers**, using the email of the driver's Bataeño Pass account.
2. The **driver role**. Creating the driver record pre-approves that email for it.

The first time the driver signs in, the server matches the Bataeño Pass account to the driver record by email, links them, and applies the role. If nothing matches, the app refuses the sign-in with "not a driver". (The server keeps pre-approved emails in the `allowed_staff_users` table, because a user row can't exist before the person's first Bataeño Pass sign-in.)

## How it works in the code

Roles and permissions are PHP enums in `libresakay-full/app/Enums/StaffRole.php` and `StaffPermission.php`. Each role lists the permissions it grants. Super Admin skips every check.

- **Routes** are protected with middleware, for example `->middleware('permission:manage-buses')` or `->middleware('role:driver')`.
- **Vue pages** read the current user's permissions from `auth.permissions`, which the server shares with every page.
- **The Android apps** get a token with limited rights. The driver app's token can only call `/api/v1/driver/*`. The kiosk's token can only read its trip and post taps.

To give yourself a role on your local copy, sign in once with Bataeño Pass, then run:

```bash
php artisan auth:promote-staff you@example.com --role=admin
```
