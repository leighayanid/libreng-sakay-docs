Putting a new bus into service touches all three apps. This page lists the steps in order, in one place. Each step links to the page with the details.

The short version: **a driver needs a driver record before they can sign in, a bus needs a published schedule before the driver sees a shift, and a bus needs an online kiosk before the driver can start.**

## How the pieces find each other

The driver app and the kiosk never talk to each other directly. Each one talks only to the web app's API, and the server connects them through the **bus**:

```text
 Driver (Bataeño Pass sign-in)            Kiosk (enrollment code)
        |                                         |
        |  driver record, matched by email        |  linked to one bus
        v                                         v
     Shift  ----------- names the ----------->  Bus
  (from a published schedule: route + bus + driver + hours)
```

- The **driver** gets their shifts because a published schedule names them.
- The **kiosk** knows which trip to count because it's linked to the bus that the shift uses.
- The server lets the driver press **Start trip** only when that bus's kiosk is online.

In boarding mode both run on the driver's phone, but they still sign in separately and hold two separate keys. See [Two identities on one phone](/kiosk/overview#two-identities-on-one-phone).

## The steps

::steps{level="3"}
### Add the bus (Admin)

**Buses** page: bus number, plate number, seat capacity, condition and status. If the bus needs an inspection, record it on the **Inspections** page. A bus that **failed** inspection can't start a trip.

See [Setting up service](/admin/setting-up-service#add-the-bus).

### Add the driver (Admin)

**Drivers** page. Enter the driver's **Bataeño Pass email** exactly, and set the driver to **active**.

This record is what lets the driver in. Creating it pre-approves that email for the driver role. Until it exists, the driver app refuses the sign-in with "not a driver".

See [Roles: how a driver gets access](/getting-started/roles#how-a-driver-gets-access).

### Add the route and its stops (Admin)

**Routes** page. Click the map to place the stops in travel order. The road path between them is filled in automatically. The route must be **active** for a trip to start on it.

See [Setting up service](/admin/setting-up-service#add-the-route-and-its-stops).

### Write a schedule and publish it (Admin)

**Schedules** page: route, bus, driver, weekdays, hours and date range. Then press **Publish**. A draft creates nothing.

Publishing creates one **shift** per day for the next 7 days, and a job tops them up every night at 00:30. Check the **Schedule Board** to see them.

See [Setting up service](/admin/setting-up-service#write-a-schedule-and-publish-it).

### The driver signs in (Driver app)

The driver installs the driver app and taps **Sign in with Bataeño Pass**. The server matches the account to the driver record by email and links them. This only has to happen once per phone.

The **Trip** tab then shows the driver's next shift. If it says **Standby**, no published schedule names this driver for an upcoming day.

See [Driver app: how a driver signs in](/driver-app/overview#how-a-driver-signs-in).

### Link a kiosk to the bus (Admin, then Kiosk)

The kiosk doesn't use Bataeño Pass. It needs a one-time **enrollment code** instead:

1. **Kiosks → Create**: pick the **bus** and name the device.
2. Press **Generate enrollment code**. The code works **once**, for **15 minutes**.
3. On the phone, open boarding mode (or the kiosk app) and type or scan the code on the enrollment screen.

The admin can also press **Send code to driver**, which delivers the code to the bus's driver inside the driver app.

See [Kiosk setup](/admin/kiosk-setup#linking-a-kiosk-to-a-bus).

### Check the kiosk is online (Admin)

The **Kiosks** page should show the kiosk as **Active** and online. A kiosk is online when it checked in within the last **3 minutes**. In boarding mode this mostly means the driver app is open on the phone.

On the phone, the kiosk shows **Waiting for trip** once the bus has a shift today.

### Start the first trip (Driver app)

At the starting point, within the shift's time, the driver presses and holds **Start trip**. The kiosk switches to **Tap your pass** within a few seconds, and passengers can board.

See [Running a trip](/driver-app/running-a-trip#_2-start-trip).
::

::note
The server must also be running its background processes (queue worker, Reverb and scheduler). Without the scheduler, no new shifts are created and kiosks never show as offline. See [What has to be running on the server](/getting-started/how-it-works#what-has-to-be-running-on-the-server).
::

## When something doesn't work

| What you see | Usually means | Fix |
| --- | --- | --- |
| Driver app says **"not a driver"** | No driver record with that Bataeño Pass email | Add the driver on the **Drivers** page, with the exact email |
| Trip tab shows **Standby** | No published schedule names this driver | Publish a schedule, or check the **Schedule Board** for the date |
| **Start trip** is greyed out: no online kiosk | The bus has no kiosk, or it hasn't checked in for 3 minutes | Enroll a kiosk for this bus, or open the driver app again so boarding mode checks in |
| Start refused: too early or too late | Outside the shift's hours | Wait for the shift, or change the hours on the schedule |
| Start refused: route, bus or driver | Route inactive, bus failed inspection, or driver suspended | Fix the record on the Routes, Inspections or Drivers page |
| Enrollment code rejected | Code already used, or older than 15 minutes | Generate a new code |
| Kiosk shows **No shift assigned** | The kiosk's bus has no shift today | Check the schedule uses this bus |
| Taps count on the **wrong trip** | The driver moved to another bus, but the kiosk is still linked to the old one | **Rebind** the kiosk to the new bus on the **Kiosks** page |
