A kiosk doesn't sign in with Bataeño Pass. Instead, an admin gives it a one-time **enrollment code**, and the kiosk trades that code for its own long-lasting key. From then on, the kiosk belongs to one bus.

Today the "kiosk" is usually the driver's phone in boarding mode. The steps are the same for the dedicated kiosk terminal.

![Kiosk setup page](/images/admin/14-kiosk-setup.webp)

## Linking a kiosk to a bus

1. The admin opens **Kiosks → Create**, picks the **bus**, and names the device (for example "Bus 12 front door").
2. The admin clicks **Generate enrollment code**. The code works **once**, for **15 minutes**. The page also shows it as a QR code (`LSK-ENROLL:<code>`) that the phone's camera can scan.
3. On the phone, the code is typed in (or scanned) on the enrollment screen.
4. The phone calls `POST /api/v1/kiosk/enroll`. The server checks the code, creates a hidden account for this kiosk with the Scanner Operator role, and returns a key (a Sanctum token) that can only record taps. The kiosk is now **Active**.

:phone-shots{:shots='[{"src":"/images/kiosk/01-enroll.webp","caption":"Kiosk enrollment screen"}]'}

The admin can also press **Send code to driver**. This sends the code to the bus's assigned driver as a special message in the driver app. The driver can reveal it once, and the admin can cancel it. This is handy when a kiosk has to be enrolled again out on the road.

The code for all of this is in `app/Actions/Kiosks/` (`IssueEnrollmentCode`, `EnrollKioskDevice`, `SendEnrollmentCodeToDriver`).

## Other kiosk actions

| Action | What it does |
| --- | --- |
| **Rebind** | Moves the kiosk to a different bus without enrolling again. |
| **Revoke** | Cancels the kiosk's key. The kiosk falls back to the enrollment screen. |
| **Delete** | Removes the kiosk record. |

A kiosk's status is **Pending enrollment**, **Active**, or **Revoked**.

## How the server knows a kiosk is online

An enrolled kiosk sends a small "I'm alive" message (`POST /api/v1/kiosk/heartbeat`) every 60 seconds. It includes the app version and how many taps are waiting to upload.

A kiosk counts as **online** if it's Active and its last heartbeat was less than **3 minutes** ago (`KIOSK_OFFLINE_AFTER_MINUTES`). The Kiosks page shows this, and an alert is raised when a kiosk stays offline too long.

## The "online kiosk required" rule

By default a driver **cannot start a trip** unless their bus has an online kiosk. Otherwise nobody on that trip would be counted. The driver app greys out **Start trip** and shows why.

:phone-shots{:shots='[{"src":"/images/driver/04-no-kiosk.webp","caption":"Trip blocked because there is no online kiosk"}]'}

To keep the driver's screen up to date, the server checks every 10 seconds whether any kiosk went online or offline, and pushes the change to the driver app (`SyncKioskStartGate`).

The rule can be **switched off for the whole fleet** on the Kiosks page. Trips then start without a kiosk, and no riders are counted. The switch is saved as the `kiosk.start_gate_required` system setting.

::note
With boarding mode, the kiosk and the driver app run on the **same phone**, so "the kiosk is online" mostly means "the driver app is open". If Android closes the app before a trip starts, heartbeats stop, and after 3 minutes the driver's own Start button is blocked. Opening the app again fixes it. `libresakay-driver-app/docs/kiosk_in_driver_app_plan.md` (section 4) discusses this.
::
