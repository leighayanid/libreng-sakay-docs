The driver app (`libresakay-driver-app`) is an Android app. Drivers use it to run their shift: start a trip, mark each stop, end the trip, and read messages from dispatch. While a trip runs, it sends the bus's GPS position to the server.

It also contains the **kiosk** as a full-screen **boarding mode**, because the dedicated kiosk terminals haven't arrived yet. That part is covered in the [Kiosk](/kiosk/overview) section.

## The five tabs

| Tab | What the driver sees |
| --- | --- |
| **Trip** | The next shift, or the running trip with a map and the stop buttons. Used most of the time. |
| **Messages** | Chats with dispatch. |
| **Schedule** | All upcoming shifts, with an All / AM / PM filter. |
| **History** | Past trips with duration and passenger count. Tap one for a recap with the route map. |
| **Settings** | Profile, light/dark theme, the boarding-mode lock (see [Kiosk](/kiosk/overview)), app version, sign out. |

While a trip is running, the bottom tabs are hidden and the Trip tab stays on screen.

## How a driver signs in

1. The driver taps **Sign in with Bataeño Pass**. The app opens the Bataeño Pass login page in a browser tab.
2. After login, Bataeño Pass sends the app a one-time code, which the app swaps for a Bataeño Pass access token. (This is the standard OAuth "Authorization Code with PKCE" flow, done by the AppAuth library. No secret is stored in the app.)
3. The app sends that token to our server: `POST /api/v1/driver/auth/bataeno-pass`.
4. The server asks Bataeño Pass who the token belongs to, finds the matching driver record, and returns **our own token** (a Sanctum token that can only call `/api/v1/driver/*`).
5. The app stores that token encrypted on the phone and uses it for every call after.

If the server says the account isn't a driver, the admin hasn't created a driver record with that email yet. See [Roles](/getting-started/roles).

## How the code is laid out

Everything is in `app/src/main/java/com/example/librengsakaydriver/`. The kiosk lives in a separate module, `kiosk/`.

| Folder | What's inside |
| --- | --- |
| `ui/` | The screens. `DriverShell.kt` holds the tabs. `cockpit/` is the Trip tab. `boarding/` opens the kiosk. |
| `api/` | The list of server calls (`DriverApi.kt`) and the shapes of their data. |
| `data/` | Getting data, and the on-phone queues that keep working without signal. |
| `location/` | `TripLocationService`, which sends GPS in the background during a trip. |
| `auth/` | Bataeño Pass sign-in and the signed-in session. |
| `di/AppContainer.kt` | Creates and connects all the parts. There's no Hilt or Dagger, just plain code. |

The app is written in Kotlin with Jetpack Compose. It uses Retrofit for server calls and MapLibre for the map.

The API address and Bataeño Pass settings are set when building, through Gradle properties (`driverApiBaseUrl`, `bataenoPassClientId` and others). The repository README lists them.

## The web version (fallback)

The web app has its own driver page at `/driver/trip`, which a driver can open in a phone browser. It does the same things (start, stops, end, SOS, messages) and calls the same server actions. Use it as a backup if the app has a problem. It **can't** do boarding mode.

Code: `resources/js/pages/Driver/` and `app/Http/Controllers/Driver/` in `libresakay-full`.
